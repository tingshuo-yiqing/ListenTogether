# 一起听歌 · UI 设计与原生实施规格

日期：2026-10-01（Asia/Shanghai）。状态：**精简版已落入 Android Kotlin / Jetpack Compose 源码；本轮构建、APK 与 MuMu 结果见 [Android 记录](test-results/2026-10-01-android-ui/README.md)**。存量 v2 独立验收仍未通过，真机/双真机待办未关闭。

用户先确认「设计稿＋可点击原型」，本轮已要求直接实施 Android 原生 UI，方向为「温暖、轻盈，适合和朋友一起听」。以 2026-10-01 精简版 HTML 与明确调整要求为参考，合并重复入口、减少歌曲列表辅助信息；HTML 保留视觉/交互参考，不新增网页原型，不使用 WebView 包装。功能约定仍以 [README](../README.md)、[协议](protocol.md) 和 [队列 / 聊天 v2 规格](ListenTogether-queue-chat-design.md) 为准；项目进度仍以 [verification.md](verification.md) 为唯一事实来源。

可点击原型：[docs/ui-prototype/index.html](ui-prototype/index.html)。HTML 内嵌全部样式、脚本、矢量图标与示意封面，下载这一文件后可直接打开，无需伴随资源目录或联网。封面和歌词仅用于排版示意。原型在浏览器内存中模拟界面、队列、聊天与连接状态，不连接后端、不保存房间、不播放音频。演示成功只说明交互设计可查看，**不证明 [v2 独立验收缺陷](test-results/2026-09-30-queue-chat-acceptance/README.md) 已修复**，也不代替 APK / 真机验收。

## 1. 方向与现状

当前 Android 使用 Jetpack Compose / Material 3，`ui/theme/` 已应用暖白、松绿与柔杏色的固定语义方案，默认 `dynamicColor=false`。依用户最新反馈，右上主题图标仅提供「浅色/深色」，默认浅色，保存选择并同步系统栏图标颜色；旧 System 偏好回落浅色。此前 Google 蓝 + Monet 属历史实现；本轮仍沿用原 RoomClient、PlaybackService、真实封面缓存和 LRC 链路，未把示意素材或模拟成功写入产品。

新方向保留暖纸底、深绿文字与深绿常驻播放器，以留白和简洁图标减少信息量。当前歌曲只在底部迷你播放器展示，队列专注待播歌曲；邀请操作统一在成员面板，展开播放器同时展示封面与歌词。当前固定语义色板已作为默认，提供保存的浅 / 深主题切换；不新增封面取色算法、炫光或渐变特效。深色模式保持同样层级，迷你播放器改为浅绿，维持控制可读性。

本轮综合 ui-ux-pro-max 检索与项目约定，取舍如下：

- 音乐类设计系统命中的 OLED / 靛蓝绿色、网页展示模式与西文字体，不直接用于这款中文原生应用。
- Soft Minimalism 检索命中的 Swiss 风格偏工具，仅采纳清晰层级、留白与内容优先，不照搬视觉模板。
- 错误恢复指引用于失败保留输入、反馈对应操作、提供恢复入口；Compose 指引用于语义色板、稳定列表 key 与状态分层。
- 中文采用 Android 系统字体；原型使用本机系统中文字体，不下载外部字体。结构图标使用同一套矢量线性风格，emoji 仅出现在用户昵称与消息内容。
- 本次图标语义检索命中 `icon-context-accessibility`：导航、退出、随机点歌、加入等图标按钮保留动作名称与选中 / 禁用状态，简化视觉信息不删去读屏语义。
- 参考 [Android 官方 Jetchat 示例](https://github.com/android/compose-samples/tree/main/Jetchat) 的聊天状态组织与主题方式（[Apache-2.0 许可证](https://github.com/android/compose-samples/blob/main/LICENSE)），只参考思路，不复制页面或整段实现。
- 长按拖排的边缘阈值与滚动速度设计参考 [SortableJS AutoScroll 说明](https://github.com/SortableJS/Sortable/tree/master/plugins/AutoScroll)；单文件原型自行实现可取消手势，不引入 SortableJS 依赖或复制代码。

## 2. 设计原则与范围

1. 房间默认进入队列；待播列表不重复展示当前曲，当前曲集中在迷你播放器，点歌和聊天各自保留状态与滚动位置。
2. 成员摘要、连接反馈和迷你播放器在三页切换时保持位置；软键盘占用底部时收起迷你播放器，键盘关闭后恢复，播放继续。
3. 房主管共享播放与排序；成员撤回自己的待播，播放键只暂停 / 恢复本机跟听。
4. 操作中的、失败的、暂未确认的结果明确区分，保留重试需要的输入与身份。
5. 暖色建立亲近感，信息层级主要依靠字号、留白与布局，状态不依赖颜色猜测。

主设计为五个视图：首页、队列、点歌、聊天、展开播放器。成员/邀请、主题选择与退出确认为辅助弹层；待播删除使用两次左滑。手机房间界面只有迷你播放器可展开播放器；原型外侧的屏幕导航、角色切换、场景切换和设计说明用于评审，不进入 Android 产品界面。按用户最新要求，本轮只设计正常字号的手机竖屏与浅 / 深主题，取消两倍字号和手机横屏模式；桌面评审工作台仍保留。

沿用已确认的边界：不恢复首页标语、欢迎大卡、动态流 / 系统事件消息、头像选择器、收藏 / 喜欢、播放历史、跨曲上一首、歌词回位按钮或歌单长图。服务器地址只在高级设置与邀请确认中出现，不放到首页常显区域或房间摘要。当前接口未下发 `album`，不增加专辑字段。

## 3. 设计 Tokens

### 3.1 色彩

Android 配色、系统字体 sp 字阶与圆角集中在 `ui/theme/Color.kt`、`Theme.kt`、`Shape.kt`，映射到 Material 角色。原型参考映射保留在 [单文件 HTML](ui-prototype/index.html) 的 `<style>` 中；表中 warning 为设计角色，本轮未增加独立警告控件。

|---|---|---|---|

| `surface` | `#FFFEFA` | `#20322A` | 表单、菜单、展开页 |
| `surface-soft` | `#EEEFE7` | `#2B3F34` | 气泡与次级区块 |
| `surface-raised` | `#FFFFFF` | `#2A3D33` | 抬升表面 |
| `onSurface` / `ink` | `#263C35` | `#F2F1E8` | 主文字、主要图标 |
| `onSurfaceVariant` / `muted` | `#5E685D` | `#BEC8B9` | 歌手、必要状态与说明 |
| `primary` | `#285A47` | `#B5D8BD` | 主按钮、选中页签、进度 |

### 3.2 字阶与文字

Android 用系统中文字体与 `sp`；网页以 CSS px 表现相近比例。以下为正常字号的 Compose 目标级别，本轮不提供两倍字号切换。

| 用途 | 字号 / 行高 | 约束 |
|---|---|---|
| 首页主标题 / 播放曲名 | 26–31 / 34–40 | 600，允许换行 |
| 应用顶栏 | 20 / 28 | 600 |
| 区块标题 | 16 / 24 | 600，导航改为有选中底色的图标 |
| 列表曲名 / 正文 / 输入 | 16 / 24 | 曲名 600，正文 400 |
| 歌手 / 状态 | 14 / 20 | 400，长昵称自然换行 |
| 时间 / 辅助标签 | 12 / 18 | 不承载主要操作说明 |
| 进度操作时间 | 12–14 / 18–20 | 仅操作滑条时显示，等宽数字 |

曲名默认最多两行，歌手可换行；歌曲行不展示点歌人、时长或随机来源。完整曲名可通过列表多行与播放器查看。聊天原文不截断，URL / 长连续文本允许换行。头像使用服务端入房时随机分配的 15 种卡通动物图，同房成员不重复，断线重连保留；缺字段/未知 ID 才回落昵称首字素策略，兼顾 emoji、代理对与组合字符。聊天消息保存发送时头像。

### 3.3 尺寸与动效

- 4 / 8dp 主栅格：图标与文字 8、组件内 12–16、左右 20、区块间 24–28；窄屏左右可降为 16。原型个别 10px / 26px 为视觉微调，原生统一在 token 内处理。
- 圆角：卡片 22–24dp、按钮 12–14dp、输入容器 16dp、迷你播放器 18dp、sheet 28dp、头像全圆。普通列表不逐行堆叠阴影卡片。
- 封面：列表 48–56dp、迷你 44dp、展开正方形按可用宽度适配，不能挤走播放控制；队列不另放大封面当前曲卡。
- Android 所有触控区域至少 48×48dp；图标视觉尺寸 20 / 24dp，相邻独立操作至少 8dp 间距。侧滑动作按钮不缩小命中面积。
- 顶栏 / 页签 / 播放器按实际内容占高，列表预留实际高度；系统状态、导航、手势区域与 IME 分别处理，避免重复 inset。
- 默认内容上限沿用 560dp。小屏竖屏空间不足时播放器主体可滚动、封面缩小，关闭与播放控制仍可达；不新增手机横屏布局。
- 线性矢量图标同层同描边；主播放键可用实心符号。图标控制有动作名称，装饰图标不进语义树。
- 按压 80–150ms、页签淡入约 180ms、弹层进入约 240ms / 退出约 160ms，均可中断。减弱动效时移除非必要移动与播放动效条，保留即时反馈。

## 4. 逐屏规格

以下为精简版交互约定；第 7 节说明本轮已落入 Compose 的具体入口与边界。Android 三页状态、真实业务操作与媒体入口已接线，实际通过项只以本轮 Android 证据为准。HTML 仍只演示离线操作，不能验证队列版本冲突、网络恢复、原生手势/读屏或媒体行为；存量 v2 恢复与资源缺陷继续独立验收。

### 4.1 首页：创建 / 加入

顶栏固定「一起听歌」，加入模式有扫码。主体只有一个表单：创建 / 加入分段、昵称、加入模式的 8 位邀请码、高级设置、一个主按钮。进入即可填写。

- 「怎么称呼你」「8 位邀请码」「服务器地址」标签常显；placeholder 只作示例。切换模式保留昵称 / 码。
- 已有地址时高级设置默认折叠；首次地址空时自动展开，提供填写位置，不静默补入生产地址。
- 扫码仍走相机 / 相册选择，识别后显示邀请确认卡，确认房间与地址后再加入。拒绝相机权限仍可相册 / 手填。
- 码自动大写并可粘贴；错误靠近字段，保留其它输入。主按钮为「创建房间」或「加入，一起听」，处理中禁止重复提交，失败后恢复编辑。
- 创建成功为无当前曲的空房；加入成功默认队列。冷启动可预填保存值，不自动入房。

### 4.2 房间公共骨架

固定顶栏 → 成员摘要 → 必要状态反馈 → 队列 / 点歌 / 聊天三个图标页签 → 当前页滚动内容 → 常驻迷你播放器。

软键盘实际占用底部时，迷你播放器暂时收起，为聊天输入与点歌搜索留出空间；关闭键盘即恢复。实体键盘或零高输入法保留歌曲栏。此布局只控制显示，不改变媒体状态，MuMu 实测见 [键盘记录](test-results/2026-10-02-chat-keyboard/README.md)。

- 顶栏始终「一起听歌」。依本轮后续反馈，房间右上保留主题选择与退出两个图标；邀请仍集中成员面板。退出先显示确认，可取消或退出；退出清当前房间的媒体、草稿与未确认状态。房间码只在邀请信息显示。
- 摘要最多三个轻微重叠的动物头像（40dp 外框、12dp 重叠、主题色描边）与「3 人一起听」；更多成员通过数量说明。点击展开成员面板，显示身份与在线 / 离线，集中提供二维码、复制邀请、分享三个图标按钮；二维码在同一面板展开，不再新增邀请二级入口。清单沿用 180dp 限高基线并按竖屏视口适配滚动。
- 连接异常、本机暂停、音频失败使用统一状态区域；已连接不占大型横幅，不多处重复提示。
- 三页签只显示队列、点歌、聊天的线性图标，以选中底色和图标形态区分当前页。每个按钮仍有明确动作标签、选中语义、焦点与键盘切换；未读只计他人新消息，不把首次历史当未读。
- 三页各自记住滚动位置；切页不清草稿、不改播放、不重建房间。

### 4.3 队列：只展示接下来

删除顶部当前歌曲卡片。当前歌曲集中展示在底部迷你播放器，手机界面只从这里展开播放器；点歌和聊天同样保留这条入口。

待播列表按顺序排列，行内只保留缩略封面、歌名、歌手，不显示序号、点歌人、时长或随机来源。依本轮后续反馈，三个点菜单改为两次左滑删除：第一次左滑露出删除按钮，点击按钮或再次左滑删除，右滑收起。普通行不因信息精简而缩小触控区域，行高随长歌名与字号增高。

- 房主长按歌曲行后拖动排序；短按不启动拖动，普通纵向滚动、短距离左滑与长按排序分开识别。拖到可滚动区域上下边缘时自动滚动，便于跨屏排序；放手才提交目标位置，取消时保留原顺序。
- 第一次左滑即使距离很长也仅展开动作；再次左滑或点击才提交真实删除，回显前不假装条目已消失。原生提供「显示删除/撤回」与排序自定义读屏动作，不恢复上移/下移菜单或常驻拖动柄。HTML 保留此前菜单演示作为历史参考，本轮不继续改网页。
- 成员只可移除自己的待播歌曲，即撤回；无权限行不提供共享排序 / 移除入口。
- 操作有处理反馈，结果按服务端状态更新；409 排序冲突显示「队列已更新，请再试一次」，回显最新列表，由用户重新操作。
- 无当前曲 / 待播时为简洁空态与「点歌」。有当前曲但无待播时，列表保留待播空态，底部迷你播放器继续展示当前歌曲。
- 第一首加入后提升为暂停当前曲，点歌不自动响起；本机暂停与播放意图沿用约定。待播以 `entryId` 稳定 key，重排不能让焦点跳到其它歌。

### 4.4 点歌：搜索、加号与单首随机

搜索框配一个随机图标，每次添加一首；取消「一首 / 五首」选择。成员待播配额仍有效，可在必要反馈与评审场景中检查，歌曲行不加配额文字。

- 歌曲行只展示封面、歌名、歌手与操作，不伪造专辑字段。
- 行尾只显示 `+`，成功或已经在当前曲 / 待播中显示 `✓` 并禁用；处理时有局部反馈，动作名称仍由读屏标签完整表达。仅行尾加入触发，整行不另设同样点击，成功不强切页。
- 成员待播最多 5 首，当前曲不计；房主个人配额豁免，总容量仍为 100。
- 随机从完整曲库候选选择，原型只用有限样本；每次只添加一首，候选耗尽、配额或容量不足给具体反馈。协议已有批量能力不等于本次 UI 继续提供五首入口。
- 防抖沿用 300ms，首屏只加载一页。更多累计去重追加；响应绑定查询 / 会话代次，旧响应不能覆盖新查询。
- `CATALOG_CHANGED` 清旧分页重查第一页；失败保留查询 / 恢复入口。网络失败不能冒充「无结果」。
- 同曲、配额满、队列满、429 给具体原因。限频按 `retryAfterMs` 等待，反馈定位到操作。

### 4.5 聊天：保留表达，控制打扰

他人左气泡搭配头像 / 昵称，自己右气泡用浅绿容器，保留发送者身份，不显示每条消息的时间。不增加系统事件行。输入栏在聊天页底部、播放器上方；IME 弹起时歌曲栏收起，输入栏贴近键盘，发送按钮保持可见。

- 草稿在房间会话作用域，切页 / 配置重建保留，离房清理。
- 发送可清编辑框，但原文立即保存到本地 pending 气泡；后续发送不能覆盖前一条未确认文本。
- pending 是时钟＋「发送中…」；明确拒绝是图标＋「发送失败」＋重试；超时用「暂未确认」，不能断言未发送。
- 聊天重试复用原 `clientMessageId`、`issuedAtMs` 与原文，不生成新 ID / 刷新时间；队列等其它操作仍沿用原协议的 requestId。未过期限频 / 丢 ack 可重试；过期、换房、身份失效后先核对状态，不自动换 ID 补发。
- ack / 广播任意顺序都只呈现一个正式气泡；只有 ack 时确认本地气泡并恢复快照，不伪造服务端 seq / 时间。
- 服务端最近 100 条已确认消息滚动窗口，实时事件也裁剪；pending / 失败本地项另行管理。超窗口缺口提示较早消息无法恢复。
- 翻历史时新消息不抢滚动，显示「有新消息」入口；主动回到底部才清对应未读，进聊天页不等于全部已读；自己发送后滚到自己的气泡。
- 空白不可发；校验 500 Unicode 码点、UTF-8 2048 字节与协议帧上限，允许换行 / emoji，错误保留原文，不能用 UTF-16 length 当字数。
- 聊天 / 待播变化不触发播放器 load / seek / 变速：这是 v2 修复验收项，网页不能验证。

### 4.6 展开播放器：封面与歌词同时呈现

仅由迷你播放器打开完整 `ModalBottomSheet`，上方有关闭。主区域按大封面 → 歌名 → 歌手 → 歌词上下排列，封面和歌词同时可见；封面不再承担切换操作。小屏竖屏下主体可滚动，底部控制保持可达。

- 底部集中放置进度条、播放 / 暂停、下一首；删除「回到开头」与常驻权限说明，不增加收藏 / 喜欢 / 跨曲上首。房主下一首 = `skip-next`，保留播放意图。
- 当前曲存在而待播为空也可跳过，结果清空当前曲并停；完全无当前曲不显示旧曲控制。
- 成员只暂停 / 恢复本机，无权限的共享 seek / 跳过不提供可点击动作。权限通过可用控件与读屏动作名表达，读屏明确「暂停本机」「恢复跟听」。
- 时间数字平时隐藏，仅操作进度条时显示当前预览位置与总时长；触摸、鼠标与键盘调整均可查看，操作结束后收起。滑条始终提供完整可访问的进度值，视觉隐藏数字不删去语义。
- seek 乐观预览 / 确认沿用现有规则，超时显示待确认；切条目 / 清当前曲清掉旧预览。
- 当前歌词加粗并用主题强调，未唱行次文字色。手动与惯性滚动结束 3 秒自动恢复跟随，再滚则重计时，不加回位按钮。
- 区分歌词加载、无歌词、读取失败；切歌不露上首歌词。清当前曲后关闭 / 替换展开内容，迷你播放器与媒体通知清旧曲，本机暂停不能绕过清理。

### 4.7 邀请与通知栏

成员面板是房间内唯一邀请入口，集中提供二维码、复制邀请与分享；二维码在该面板展开，保留高对比与留白。邀请由统一编解码器生成，仅公开码 / 地址，不含成员令牌。分享使用系统面板。离线原型的二维码 / 分享标为示意，不能当跨设备扫码验收。

当前原生通知栏沿用系统媒体样式，房主下一首走 `skip-next`、回开头 seek 0；这是现状，不把它作为本次展开页保留「回到开头」的依据。后续若调整通知栏控件需另有原生任务与设备证据；成员不提供全房间控制。空当前曲清媒体，不残留旧标题。网页不能代测通知栏外观与按钮行为。

## 5. 状态矩阵

以下均为目标行为，演示不等于网络、协议或 Android 已实现。

| 场景 | 展示 | 恢复 / 保留 |
|---|---|---|
| 表单错误 / 连接失败 | 字段具体错误 / 统一失败反馈 | 保留昵称、码、地址 |
| 连接中 / 加入歌曲中 | 主按钮 / 行内处理反馈 | 禁止重复点击，等确认 |
| 新建空房 | 空态，无旧播放器 | 去点歌，首曲保持暂停 |
| 有当前曲、无待播 | 底部迷你播放器＋待播空态 | 点歌 / 跳过，按原播放意图处理 |
| 同曲 / 配额 / 容量满 | 已点或具体原因 | 禁止重复；可撤回自己的待播 |
| 单首随机 / 候选耗尽 | 一首加入反馈 / 具体原因 | 保留成功结果，不重复加入 |
| 长按排序 / 拖动取消 | 正在移动的歌曲与目标位置 | 边缘自动滚动；放手提交，取消保留原顺序 |
| 排序 409 | 最新列表＋队列已更新 | 用户按最新状态重新操作 |
| 429 | 对应操作反馈 | 等 retryAfterMs，保留原身份 |
| 搜索 / 分页 | 占位 / 底部加载 | 保留已有页，隔离旧查询响应 |
| 聊天 pending / 超时 / 拒绝 | 原文气泡＋对应图标 / 文案 | 原身份重试，不丢文本 |
| 缺口 / 缺块 | 恢复反馈 | 完整快照原子应用，超窗说明 |
| 翻历史有新消息 | 未读入口，保留位置 | 主动回底部才清相应未读 |
| 重连中 | 连接中断，正在重连 | 保留页 / 草稿，不盲重放副作用 |
| 本机暂停 | 暂停提示与明确播放键 | 显式点击才能恢复跟听 |
| 身份失效 | 需要重新加入 | 换身份，不带旧 pending 自动发送 |
| 426 / 旧服务器 | 兼容性终态说明 | 返回首页，不无限重连 |
| 能力探测网络失败 | 可重试连接失败 | 不能冒充不兼容 |
| 部分能力缺失 | 能力说明 / 隐藏不可用入口 | 按能力标志判定，不假设三页都有 |
| 音频 / 歌词错误 | 对应媒体反馈 | 其余可用队列 / 聊天仍可操作 |
| 清空 / 退出 / 换房 | 清旧媒体、草稿、反馈 | 迟到响应不能显示上一房间 |
