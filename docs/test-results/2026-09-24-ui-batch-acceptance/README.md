# UI 批次真机验收：批次 1 邀请口令 + 批次 2 成员可视化/歌单搜索（2026-09-24）

## 结论

**通过，零产品缺陷。** 批次 1（邀请口令闭环）与批次 2（成员状态可视化 + 歌单搜索）全部可自动化场景在真机实测通过；三项场景（智能识别 / busy 禁用 / 分享面板弹出）自动化无法模拟，如实标注待人工验证。验收过程中出现的全部 FAIL 均归因为自动化驱动侧问题（输入法拦截、视口、时序、僵尸会话），已定位并修复驱动，未改任何产品代码。

## 环境与方法

- 设备：PHQ110（OPPO A1 Pro / Android 14），USB 调试（serial `fbddbe8`；无线 mDNS 通道中途失效后改 USB）。
- 被测 APK：**2CBA5913…**（批次 2 构建，70 项单测；批次 1 场景同轮重验）。装包方式 `adb install -r`，每轮 Success。
- 后端：本地演示后端（`MEDIA_DIR=demo-media`，`http://127.0.0.1:3000`，设备侧经 `adb reverse` 访问）；每轮 `device-side curl /health` 校验。
- 驱动：`.workbuddy/b1_driver.py`（沿用 W1 驱动的单进程纪律：连接→装包→reverse→场景序列→导出诊断，全部在同一进程内完成，规避陷阱 2.7/3.5）。阶段：`accept` → `retest` → `retest2`（手填/确认卡对照实验）→ `tail`（选歌+播放+拖动）→ `err`（失败横幅）。全量日志在 `evidence/b1-run.log`。

## 自动化边界与已知驱动坑

- **陷阱 2.11（本次新坑，已回填 development-pitfalls.md）**：ColorOS 输入法对 uiautomator 不可见、`keyevent 111` 不收起，底部区域（y≥约 1500）的 `input tap` 全被输入法拦截——本轮「加入按钮无响应」的最终根因，改用 `keyevent 4` 收起后全部恢复。
- LazyColumn 未组合的行不在 dump 中：目标行需先滚动再查找；选中后滚回播放卡核验「当前歌曲」。
- 服务端空房 5 分钟回收后客户端可能停留在房间页（僵尸会话，UI 操作全部无效）：驱动先看 `/health` rooms 计数，残留会话一律退出重进。
- 播放动画期 `uiautomator dump` 会失败（既有陷阱 3.1），重试或以 `dumpsys media_session` 为准。

## 边界

- 结论只对参与设备（PHQ110）、本网络条件与 demo-media 曲库成立。
- 未覆盖：暗色主题下批次 2 头像可读性（暗色冷启动无白闪此前已验）、平板/大字体、双机同步精度（M2 仍挂起）。
- 本轮未改任何产品代码；验收驱动与证据归档于本目录。
