## 1. 测量方案（本轮补齐，工具已入库可复跑）

- **客户端 diag 口径（主）**：双机 `files/diagnostics/diag-*.jsonl` 的 `type=playback` 事件（每秒一条），以 `estimatedServerMs` 统一服务端时钟，按 `(trackId, 1 秒桶)` 配对取 `playerPositionMs` 差值；`correction=seek/speed/load` 分级统计变速追赶（交接单第六节口径：500ms–2.5s 变速、>2.5s seek）。统计工具 `scripts/m2-diag-stats.mjs`。
- **外置 dumpsys 口径（交叉）**：`scripts/m2-sync-sample.mjs` 每秒对两台各取一次 `dumpsys media_session`（圈定 `package=com.listentogether.app` 会话），同一主机时钟；顺序读取的固有时延按各自读取时刻与速度外推校正（`gap_skew` 列）。
- 音频层同录比对未做（标准允许：无法录音则只报告进度层误差，音频层验收仍待完成）。

## 2. 10 分钟连续播放测量（自动顺播跨《红豆》《倔强》《囚鸟》3 首）

| 指标 | 结果 | 门槛 |
|---|---|---|
| 可比样本占比（双端同轨且非暂停/缓冲） | **99.5%**（392/394 桶） | ≥90% ✅ |
| 跨端进度偏差 ≤500ms 占比（diag 口径） | **28.1%**（n=392，p50=732ms，p90=1976ms，max=2593ms） | ≥95% ❌ |
| 跨端偏差 ≤500ms（dumpsys 口径，598 ticks） | 49.0%（≤1000ms 70.2%） | 参考口径 |
| A（真机）自身 driftMs | **p50=258ms / p90=276ms**，窗口内 0 次 seek、34 次 speed | — |
| B（MuMu）自身 driftMs | p50=934ms / p90=1720ms，**speed 纠正 448 次**（约 75% 时间处于变速追赶）、0 次 seek、4 次缓冲 | — |

**根因判明**：真机自身同步紧密达标（p50 258ms），跨端偏差几乎全部来自 **MuMu 模拟器音频时钟慢约 2–3%**——客户端按设计持续以变速追赶把漂移压回（锯齿形态：漂移爬升 → 变速/seek 回带内，采样 CSV 的 `gap_skew` 列可见完整循环），未出现失控或长时间失步。**95%≤500ms 门槛在此配对下未达，主因是模拟器时钟而非同步机制**；门槛的最终判定仍需真机+真机组合。

## 4. 结论与边界

- **M2 判定**：同步机制与三场景在真机+模拟器配对下验证通过；**95%≤500ms 稳态门槛未达，主因判明为模拟器音频时钟漂移**（证据：真机自身 drift p50=258ms 达标 vs MuMu p50=934ms 且 75% 时间处于变速追赶）。M2 从「缺第二台设备完全挂起」更新为「**真机-真机组合复测待办**」——测量工具与流程已全部就绪，第二台真机到位后即可按本轮同样口径出权威结论。
- 挂起项要求「不调整同步参数」已遵守：本轮零代码改动，未动 SyncMath/变速参数。
- 一个待真机复测确认的观察：MuMu 的时钟漂移率（~2–3%）使客户端几乎持续处于 500ms–2.5s 的变速带内；若真机-真机也出现持续性稳态漂移，可考虑「持续漂移时保持小幅常驻变速」的参数方向——本轮未动，仅记录。
- 边界：音频层同录比对未做；15 人负载项沿用既有 load15 证据，本轮未重跑；MuMu 为 x86_64 模拟器（ARM 转译），不代表真机音频路径。
