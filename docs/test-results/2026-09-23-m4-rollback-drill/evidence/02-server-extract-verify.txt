## 分析（本节结论已回填 docs/development-pitfalls.md 8.7）

1. **清单 35/35 行全部以 CRLF 结尾**（od 直证 `g z \r \n`）。
2. **`sha256sum -c` 本身容忍 CRLF**：[0b] 中 tarball 行（同样带 CR）在 /tmp 下校验成功并打印 `OK`；
   后续 FAILED 行的原因是 `demo-media/*` 当时确实不在 /tmp（尚未解包），与 CR 无关。
3. **失败的真凶是 GNU grep 的 `$` 锚点**：`grep 'tar\.gz$'` 在 CRLF 文件上匹配 0 行 → 管道给
   `sha256sum -c` 的是空输入 → 报 `no properly formatted checksum lines found`。
   本机 MSYS grep 会自动吞掉行尾 CR，故同一条命令**本地通过、服务器静默返回空**。
4. 处置：服务器侧 `tr -d '\r'` 生成 LF 副本后再按行过滤校验（本文件 [0c]/[2]）→ **34/34 OK**。
   同时已修正 `scripts/package-deploy.ps1`，今后清单直接输出 LF，不再需要转换。
