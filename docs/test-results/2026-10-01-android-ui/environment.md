## 本轮 UI 接线与存量缺陷的区分

本轮客户端接线目标是保留聊天原文及原操作身份、展示发送 / 未确认 / 失败 / 已确认状态，且按真实 `result.messageId` 对账；点歌处理态在 ack / 关联错误 / send 失败 / 5 秒超时结束，成功勾只看真实播放与队列快照。聊天重试等待和到期均采用手机单调时钟，500 个 Unicode 码点 / UTF-8 2048 字节先校验，未接入时不清草稿。

仍须保留原 [v2 独立验收](../2026-09-30-queue-chat-acceptance/README.md) 挂账：服务端认证 WS `null` 崩溃风险、缺口 / 缺块恢复与快照排序、实时 100 条窗口、播放观察者隔离、播放命令去重、房间字节预算、队列分块和发送调度、限频错误缺客户端消息 ID、连续失效条目消费。ack 丢失而广播先到时，当前协议没有 `clientMessageId`，本地未确认项不能仅凭同文猜配对；用户原 ID 重试拿到 ack 后再按服务端身份收敛。

双真机同屏 / 声音、M2 95% 门槛、真机系统字体与 TalkBack、R8 流畅度仍须专项证据，本轮 MuMu 正常竖屏检查不能关闭它们。
