# LOAD-15 负载脚本与本地 10 分钟记录（2026-09-22）

任务编号：LOAD-15。操作者：AI 辅助自动化（本地后端，无手机参与）。
结论：**脚本交付并通过本地 10 分钟播放速率记录**；本机回环容量另测（吞吐模型）。不冒充 15 台手机验收，不代表云端结果。

## 交付物

- `scripts/load15.mjs`：
  - 通过正常流程建房 + 成员加入（默认 15 人，受 409 上限保护），**每名成员持有 WS 连接**（ws 客户端自动回 pong），令牌只存脚本内存；
  - playback 模型：按目标码率（默认 192kbps）做节奏化 Range 读取，每秒采样每路字节；覆盖完整读取（throughput 模型内）、文件尾回绕与显式随机跳转（Range 跳转）、每名成员一次响应头到手后立即中止（读取取消）；
  - throughput 模型：无节流全量读取 `--cycles` 轮，只报告容量；
  - 选曲默认逐首探测后取**码率最高**者（`--track` 可指定）；
  - 汇总每路字节/平均速率/状态码分布/失败数/取消与跳转次数，进程 RSS/CPU 趋势（注明“本机 node 合计、仅趋势、不设阈值”）；退出码非 0 条件：非 200/206 状态、失败数>0、playback 每路平均速率 < 目标×0.9；
  - finally 关闭全部 WS 并 DELETE 全部成员资格。
- 曲库新增 `demo-media/demo-load.mp3`（合成 330Hz 立体声，11 分钟，192kbps，15.8MB）并登记 `catalog.json`；**重启演示后端后加载**。32kbps 的 demo-long 不用于码率模型（见执行单第 4 节）。

## 过程中发现并修复的脚本缺陷

- 首次 10 分钟运行失败：401×240 + 404×299（每路）。根因是脚本成员**只走 HTTP 不持有 WS**，服务端按“离线 60 秒”清扫成员（store.ts:72），随后空房间 300 秒后删除；失败分布与前 60 秒成功、其后 401、房间删除后 404 的时间线吻合。
- 修复为成员持有 WS 后，70 秒验证（覆盖清扫窗口）与 600 秒正式记录均零失败。教训已回填开发陷阱清单。

## 边界

- 本机回环 + 明文 HTTP：无 TLS、无公网 RTT/丢包、无代理；2.88Mbps 的结论不能外推到云端（执行单明确要求云端重测）。
- playback 模型是“按目标码率的字节读取模型”，不代表解码器真实拉动节奏；15 名成员不产生 WS command 消息，服务器广播负载低于真实房间（15 人房间每次操作广播 15 份快照）。
- CPU/内存为脚本进程视角；后端进程未单独采样（本机 node 进程无法拆分归属），已如实标注。未设合格阈值，仅留实测。
- 后端为单实例内存态；本次记录不代表多实例/重启后的行为。

## 清理

- 负载进程已退出，WS 全关，成员资格全删（房间留待后端内存回收）；无手机端改动；后端继续运行供演示。
