# 2026-09-29 管理器页面：视图拆分 + 列表节点缓存

范围：**只改 `scripts/metadata-manager.html`（含页面自带 JS/CSS）**，`metadata-manager.mjs` 一行未动
（已核实它只把 HTML 当文件原样吐出、不碰 DOM，其余全是 JSON API），协议、安卓、曲库文件均未涉及。

## 环境

- 夹具：`browser-check.mjs` 内置 HTTP 服务器 + 真实 Chrome（`--headless=new`，CDP 驱动），**不访问音乐平台**
- 曲库：3 首内存夹具（a/b/c，专辑甲/甲乙混合，用于验证筛选与排序）
- 门禁：脚本离线单测 **51/51**；三份页面驱动全绿
- 证据截图：`views-1280.png`（浏览视图 1280px）、`views-390.png`（390px 窄屏）

## 改了什么

1. **三视图互斥**：`浏览曲库 / 批量匹配 / 新增歌曲` 由 `body[data-view]` 驱动 CSS 显隐，当前视图的 tab 高亮
   （`aria-selected`）。原来五块功能堆在同一屏，进来就得面对编辑表单的十几个控件。切视图不碰数据：
   切走再切回，选中曲目、编辑区内容、列表顺序都还在。
2. **列表行节点缓存**（`rowCache`）：行只建一次，筛选/排序/多选/删除只改类名、勾选状态与节点顺序。
   原来每次 `input` 都整表 `innerHTML=''` 再逐条 `createElement + querySelector` 重建，曲库越大越慢。
3. **内联样式收编**：24 处内联 `style` 中的 22 处换成语义类（`.sub-note` / `.inline-row` / `.grow` /
   `.w-full` / `.align-end` / `.mt-*` / `.btn-compact` / `.file-hidden` / `.lrc-preview` / `.tabs`）。
   剩下 2 处（`#editor`、`#cover-img` 的 `display:none`）**故意保留内联**——它们由 JS 的
   `style.display` 切换，挪进类会与 JS 抢同一个属性。

## 顺带修掉的真实缺陷：版本告警误报

页面把期望版本硬编码为 `20260929-lyrics-preview` 且用**严格相等**比较，而服务端 09-29 加转码后已升到
`20260929-hi-aac`——于是「服务端比页面新」被判成「管理服务仍是旧版本」，页面顶部常驻误报，还把用户引去
重启一个并不旧的进程。改为比较常量 `PAGE_SERVICE_VERSION` 的**下界**（版本号是日期串，直接比大小）：
服务端不比页面旧即视为兼容，新增服务端能力时再抬下界。

回归覆盖：同版本无告警 → `20260930-xxx`（更新）无告警 → `20260928-1718`（更旧）必须给出重启指引 → 回到同版本恢复无告警。
因该常量已变，09-28 驱动的夹具「当前版本」同步为 `20260929-hi-aac`、「旧版本」由 `'old'` 改为 `20260927-1240`。

## 覆盖的断言

- 视图：初始 `browse`；batch/new 视图初始不可见；切换后目标视图可见且其余**互斥隐藏**；
  `aria-selected` 跟随；进入批量视图立即提示缺字段数量（不必点开始匹配才发现没活可干）
- 切视图不动数据：`currentId`、编辑区显示状态、已填表单跨切换保持
- 节点缓存：筛选/排序前后行节点带标记未被替换；`rowCache` 按 id 命中；**筛不出结果时旧行必须从面板消失**
  并给出 `#list-empty`；删曲后被删行节点与缓存一起清掉，其余行仍复用
- 多选：勾选框随多选模式出现/隐藏、勾选进 `picked`、删除按钮联动、**勾选框点击不冒泡成选中编辑**、
  退出多选清空已选
- 布局：歌词输入框与上传按钮同行、歌词预览 `pre-wrap`、隐藏的文件选择器不占位；1280px 与 390px 截图
- 全程无未捕获 JS 异常

## 过程中抓到的两个自己的 bug

- **`renderList` 空结果分支提前 `return`**，把「把被筛掉的行从面板摘下来」那步跳过了——筛不出结果时旧行
  仍留在面板上冒充结果。被 09-28 驱动的 `querySelectorAll('.track-item').length === 0` 当场抓住。
  **教训**：缓存/增量更新类改写里，「早退分支」最容易漏掉收尾步骤；先写收尾再写早退。
- 新写的驱动自身有三处断言错误（专辑关键词命中数算错、排序后首行必然换人、在页面上下文改夹具数组会被
  下一次 `refresh()` 覆盖）。都已修正——页面改动的验证价值有一半来自老驱动，新增覆盖必须同样较真。
