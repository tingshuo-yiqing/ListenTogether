# 模块文档与核心代码注释规范

状态：后续开发的交付要求；本次只编写方案与模块说明，不声称已补完所有源码注释。

## 每个模块的必备文档

1. 职责与边界：负责什么，状态由谁持有，依赖谁，不能越权操作什么。
2. 代码入口：现有文件/类/函数与调用关系；计划新增入口必须标注“待实现”。
3. 数据与接口：字段类型、时间单位、可空性、错误、权限、兼容性；公共协议链接到 protocol.md，避免重复定义漂移。
   protocol.md 已附**可执行的 JSON Schema**（`## JSON Schema` 小节），由 `server/test/protocol.test.ts` 直接提取并校验实现产出的真实消息；
   改协议先改文档，实现漂移会被测试拦下。**不要**在别处复制一份字段清单，也不要在测试里另存 schema 副本。
4. 正常流程：从触发到结果的关键步骤；复杂状态转移用表或时序图。
5. 异常与资源回收：取消、超时、重连、重复回调、文件缺失、释放顺序。
6. 验证：模块自动化、跨模块集成和人工场景；区分“已通过”“待验证”“目标”。
7. 核心注释清单：哪些函数必须解释其不变量/并发/计算依据。
8. 变更记录：日期、行为改变、测试证据和剩余问题；文档不保存密码或令牌。

## 代码注释要求

Kotlin 的公共模型、状态转换、Service 生命周期、时钟算法使用 KDoc；TypeScript 的领域操作、公开接口、文件边界处理使用 TSDoc。
注释必须写清：
- 输入输出与单位；UTC/服务端时基/手机单调时钟不能混用。
- 谁可以调用；是否主线程、是否可挂起、能否重复或取消。
- 前置条件、不变量、副作用、失败返回，以及资源如何释放。
- 为什么需要代次校验、为什么先结算进度、为什么不重放离线指令等不直观决策。
- 涉及超时/阈值的来源；统一命名常量，不能在多处复制无解释数字。

不要求给明显的 getter、普通赋值写注释。不用注释掩盖复杂代码：先拆职责，再解释必要约束。
注释写中文，接口和变量名称保持英文；“以后优化”必须关联具体任务，不能把 TODO 当作功能实现。

## 验收报告字段（docs/test-results/<日期>-<场景>/README.md）

| 字段 | 必填内容 |
|---|---|
| 标识 | 任务编号、日期、操作者、通过/失败/阻塞/部分覆盖 |
| 环境 | APK hash、后端版本、设备、网络、音频输出、电池策略 |
| 操作 | 前置条件、实际命令/动作、注入和恢复时刻 |
| 数据 | 预期与实测、原始证据文件、采样频率、空档与误差 |
| 边界 | 未覆盖项、问题与下一步，不将单测结论替代真机 |
| 清理 | 清除注入、恢复测试文件、退出临时成员、只停止自身测试进程 |

负载类测试分开记录播放速率模型与最大吞吐模型，不能用平均值隐藏长停顿。代码修复同时更新有意义的回归测试、相关模块与 verification.md；仅文档交付检查差异、相对链接和状态一致性即可，不重新制造 APK 或测试通过记录。

## 完成定义

- 行为代码有适当自动化回归；不为单纯文字或低风险格式修改编写镜像测试。
- 新功能和缺陷修复有可复现步骤与期望结果，不以“没有报错”作为所有测试的判断。
- 文档、接口、注释、测试和发布记录一致；所有待测项仍明确标为待测。
- 检查 Markdown 相对链接和代码入口有效。
- 发布记录包括版本、构建命令、测试报告、APK hash、设备与服务器条件。

## 仓库清理标准（2026-09-26 定型，后续清理一律照此执行）

本标准由 2026-09-26 深夜「工作区二次清理」轮定型（证据见 verification.md 该节），适用于一切删除/精简类操作：

1. **先勘察后动手**：`git status` 确认基线干净；对待删项做引用扫描（docs/scripts/README 互相 grep，含证据目录 README）；确认目标是否被 .gitignore 覆盖。
2. **逐项给结论**：每个拟删项必须写明「是否仍被引用 / 是否影响构建测试运行 / 是否有保留价值」与保留或删除理由；**用途不确定的一律保留并标注说明**。
3. **清单先行**：先输出按路径列出的清理清单交用户确认，确认后才执行删除；不替用户决定有争议项。
4. **只动安全区**：默认只删 .gitignore 覆盖、可由源码/脚本重建或已在云端/证据目录归档的产物（构建目录、残留日志、临时探针、已上云制品的本地副本）。git 跟踪文件的删除必须逐条说明断链影响。**永不删除**：版本控制关键配置（.gitignore 等）、`docs/test-results/` 证据链、`docs/archive/`、`deploy/` 部署基线、`.workbuddy/memory/` 与可复跑驱动脚本（w1/b1/fb_driver.py、lt_*）、本地唯一副本的个人文件（如 `demo-media/有何不可.mp3`）。
5. **删后必验**：删过构建产物（如 `android/app/build`）必须全量重跑门禁 `cleanTestDebugUnitTest → testDebugUnitTest → assembleDebug → lintDebug`，确认测试实跑（非 UP-TO-DATE）、0 失败；收尾 `git status` 应为 0 变更（证明未误删跟踪文件）。
6. **登记闭环**：清理结果按「本轮新增」追加进 verification.md，写明删除项/保留项/回收体积/门禁结论；踩到新坑回填 development-pitfalls.md。
