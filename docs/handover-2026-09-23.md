## 一、用户报告的两个问题

1. **后台音乐播完后可以自动切换，但是会卡住；app 主页播完一首后进度条在动，但是没有声音（卡顿音）。**
2. **进度条端点是一根很长的竖线，不美观且占空间。**

## 二、问题 1 的调查结论（已完成根因定位）

### 取证方法

- 无线 adb 拉取设备端诊断 JSONL（`files/diagnostics/diag-*.jsonl`），共分析 3 个会话
  （昨晚 2 个 + 今早 1 个，合计约 4800 条 playback 记录）。
- 现场自动化复现被用户正在使用的 B 站播放干扰（media_session 里 PLAYING 的是 `tv.danmaku.bili`），
  未完成 A/B 实验，结论以诊断数据为准。

### 实测证据（三个会话完全一致的形态）

| 观察项 | 实测值 | 说明 |
| --- | --- | --- |
| 渲染位置推进速率 | **~0.86x**（每 5 秒窗口落后 670–740ms） | 无缓冲（零 BUFFERING 抖动）、无暂停、无焦点事件 |
| seek 纠正频率 | **每 5 秒一次**，贯穿全程（今早会话连续 24 分钟） | 校时回调每 5 秒触发一次 applyState，每次都发现 drift>500ms |
| 时钟偏移稳定性 | ±6ms / 30 分钟 | 排除校时估计振荡 |
| 服务端目标推进 | 1.001x | 服务端时钟正常 |
| 手机省电模式 | `low_power=1`、`low_power_sticky=1`（多日常开） | 已回填陷阱清单 9.1 |
| 系统混音器 underrun | `empty=491`、fifo underrun n=7647（dumpsys media.audio_flinger） | 渲染端欠载的直接证据 |
| 切歌（自动/手动）初始缓冲 | **约 3 秒**无声音，随后 1–3 次连环 seek 才恢复 | 叠加在每 5 秒风暴之上，即用户看到的"切歌后卡住" |

### 因果链

```
省电降频/后台负载 → 音频渲染线程周期性欠载（underrun）
  → 播放位置每 5 秒落后 ~700ms（听感 = 卡顿音，进度条跳变）
  → 客户端 500ms 阈值 → 每 5 秒 seek 一次
  → 每次 seek 丢弃已缓冲数据并重新起流（又一次可闻中断）
  → 切歌时再叠加 ~3 秒初始缓冲 = 长时间无声"卡住"
```

**为什么早前的真机测试没发现**：测试断言的是状态推进（PLAYING、进度走动、房间 version），
而进度走动恰好是 seek 风暴造成的；音频连续性从未被验证过。此教训已回填陷阱清单 9.2。

## 三、本轮修复内容（问题 1）

代码改动集中在客户端表现层/播放层，行为约定不变（服务端仍是播放唯一来源）：

1. **分级纠正替代"逢 500ms 必 seek"**（`sync/SyncMath.kt` + `playback/PlaybackService.kt`）：
   - 500ms 仍是"需要纠正"的触发线（`needsSeek` 不变，协议验收目标不变）；
   - 500ms–2.5s：**连续变速追赶**（Sonic 变时值不变调，±4%~±12%），不丢缓冲、无声音缺口；
   - 超过 2.5s：才真正 seek（会重新缓冲，产生一次可闻中断）；
   - 暂停/装载新曲目时倍速复位 1.0。
2. **渲染缓冲加大**（`playback/PlaybackService.kt` 的 `SmoothRenderers`）：
   AudioTrack 缓冲从默认几十毫秒加大到 ~0.7 秒（120KB），吸收省电降频下的调度抖动，直接减少 underrun。
3. **漂移自检提速**：applyState 从"仅校时回调每 5 秒"提升为"每秒一次自检"（500ms ticker 计数触发），
   纠正更及时、变速调节更平滑。
4. 诊断 `correction` 字段新增取值 `speed`（变速追赶），便于验收时统计。

验收路径：`adb shell run-as com.listentogether.app cat files/diagnostics/diag-*.jsonl` 导出后统计
`correction="seek"` 的频率——修复后正常网络下应基本消失（仅大跨度拖动/真实失步出现），
`speed` 条目只在漂移 500ms–2.5s 时出现且随后回到 1.0。

## 八、行为约定重申（防交接走样）

- 服务端为播放唯一来源；客户端所有纠错（load/seek/speed）都只是向服务端位置收敛。
- 明确点击播放才能解除本机暂停（焦点丢失/耳机拔出/401/404 等中断后）。
- 变速追赶只作用于本机渲染，不影响房间状态与他人进度；变速上限 ±12%，超过 2.5s 漂移回到 seek。
