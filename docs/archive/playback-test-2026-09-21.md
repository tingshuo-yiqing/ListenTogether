# PHQ110 真机播放测试记录

日期：2026-09-21
应用：一起听歌 0.1.0 debug
环境：PHQ110 真机通过 USB reverse 访问电脑 127.0.0.1:3000；合成 MP3 曲库。
第二个客户端为只观察房间状态的 WebSocket 测试成员，不是第二台音频播放设备。

## 本次不代表已通过

- 两台手机的真实音频同步误差；观察客户端仅验证状态广播。
- 长时间锁屏、省电限制、弱网及断网重连。
- 通知栏按钮实际点击、耳机拔出、来电/音频焦点抢占、解码错误重试。
- 非房主手机的本地暂停，以及实际云服务器带宽。

## 测试后状态

测试音已暂停，手机已唤醒，测试观察成员已移除。
应用和本机演示后端保留，方便继续手动体验。若手机显示锁屏，请正常解锁。

## 测试过程（按执行顺序）

### 1. 环境准备与连接恢复

1. 请求本机 `http://127.0.0.1:3000/health`，返回 `{"ok":true}`。
2. 首次执行 `adb devices -l` 时设备列表为空，等待用户连接并授权 USB 调试。
3. 用户确认连接后，检测到 PHQ110，设备状态为 `device`。
4. 执行 USB 端口转发，启动已经安装的应用；系统提示 Activity 已存在，将其带到前台。
5. 读取本应用 UI，确认处于昵称/服务器地址入口。

复现命令（多台手机时加 `-s 设备序列号`）：

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& $adb devices -l
& $adb reverse tcp:3000 tcp:3000
& $adb shell am start -n com.listentogether.app/.MainActivity
```

### 2. 创建房间与观察端

1. 在手机填写服务器地址 `http://127.0.0.1:3000`、昵称 `PhoneTest`。
2. 点击“创建房间”，成功显示邀请码、房主身份和两段测试音。
3. 通过 HTTP 加入一个名为 `TestObserver` 的测试成员，并建立 WebSocket 连接，记录共享状态。
4. 观察端不播放音频，只用于确认手机操作到达服务器并广播给其他成员。记录不保存成员令牌。

测试房间和邀请码仅在本次后端运行期间有效，复现时应创建新房间。

### 3. 首轮播放与自动推进

1. 在手机点击播放。
2. 观察端依次记录：A 播放 → B 播放 → B 结束后停止。
3. 用户明确反馈“听到了测试音”，补充程序状态无法单独证明的实际音频输出证据。
4. 动态 UI 抓取出现 `ERROR: could not get idle state.`。该次 XML 是旧快照，没有作为播放结果使用。
5. 截图发现 USB 用途选择框遮挡界面，关闭选择框并重新将应用带到前台；未改变 USB 用途设置。

### 4. 播放、暂停与跳转

1. 在 B 停止后点击播放，约 4 秒后读取本应用 Android 媒体会话。
2. 点击暂停，约 2 秒后读取状态，再等待约 3 秒读取一次。
3. 点击进度条中部，检查手机位置及观察端的房间位置。

实测证据摘录（不同系统采样点不要求毫秒完全一致）：

```text
播放：PLAYING(3), position=2367, speed=1.0
暂停：PAUSED(2), position=4754, speed=0.0
再次检查暂停：PAUSED(2), position=4754
跳转后：PAUSED(2), position=21988
观察端：trackId=demo-high, playing=false, positionMs=21988
```

### 5. 切歌与后台播放

1. 在暂停状态选择 A，媒体元数据切换为 A，位置归零。
2. 点击播放，约 2 秒后按 Home 返回桌面。
3. 等待约 5 秒，读取本应用媒体会话，仍为播放状态。
4. 确认当前媒体按键会话属于本应用后，执行系统媒体会话暂停指令。
5. 对照观察端的暂停广播，再返回应用。

```text
切歌：A，PAUSED(2), position=0
后台：A，PLAYING(3), position=6283
媒体暂停：A，PAUSED(2), position=7805
观察端：demo-soft, playing=false, positionMs=7819
```

系统控制通过 `adb shell cmd media_session dispatch pause` 验证。
**本次没有实际点击通知栏按钮**，因此不将通知栏 UI 点击列为已验证。

### 6. 短暂息屏播放

1. 恢复播放，约 2 秒后发送息屏按键。
2. 等待约 6 秒，查询电源状态及本应用媒体会话。
3. 电源状态为 `Dozing`，媒体会话仍为 `PLAYING`，位置为 13592ms。
4. 发送唤醒按键，并通过当前媒体会话暂停。
5. 最后一次手机采样为 `PAUSED`、17584ms；观察端最终暂停基准为 17751ms。

```text
息屏按键：KEYCODE_SLEEP (223)
电源：mWakefulness=Dozing
媒体：PLAYING(3), position=13592, speed=1.0
唤醒按键：KEYCODE_WAKEUP (224)
结束：PAUSED(2), position=17584
```

这是一次短时息屏测试，不等同于长时间省电/深度休眠验证，也不是双机同步误差测量。

### 7. 日志检查与清理

1. 获取本应用 PID，仅检查该进程近期 500 条日志。
2. 搜索 `FATAL EXCEPTION`、`PlaybackException`、`ExoPlaybackException`，未命中。
3. 关闭观察端 WebSocket 并退出其房间成员身份。
4. 保留用户手机应用和本机演示后端，停止测试声音。
5. 将结果更新至 [验收总表](../verification.md)。

## 复测方法与证据边界

- 图中坐标只适用于当时设备布局，复测应按按钮文字操作，不照搬坐标。
- 可使用 `adb shell dumpsys media_session` 查询播放器状态，只提取本应用条目；避免记录其他应用会话。
- 本记录中的数值是当次工具输出摘录，不是伪造的完整原始日志，也不代表性能统计。
- 声音是否实际输出以用户确认补充；媒体会话显示 PLAYING 本身不能证明扬声器可听。
- 房间广播和手机位置来自不同时间的采样，不能用两者之差宣称已测得双机同步精度。
